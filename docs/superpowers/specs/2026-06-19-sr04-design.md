# SR04 Ultrasonic Module Integration Design

## 1. Overview
Integrate an SR04 ultrasonic distance measurement module into the MSPM0G3507 firmware. The measurement will be non-blocking, using an external interrupt to capture pulse width and a hardware timer for time measurement. The result will be displayed on the tracking PID dashboard (Page 2) of the OLED.

## 2. Hardware Allocation (SysConfig)
*   **TRIG Pin**: `PA3` (Configured as `OUTPUT`, initial state `LOW`).
*   **ECHO Pin**: `PA4` (Configured as `INPUT` with `PULL_DOWN` or `NONE`, Interrupt enabled on both `RISING` and `FALLING` edges).
*   **Timebase (TIMER_SR04)**: A new `TIMG` instance.
    *   **Clock Source**: System Clock.
    *   **Prescaler/Divider**: Configured to produce a `1 MHz` (1 us) tick rate.
    *   **Mode**: `PERIODIC_UP`.
    *   **Period**: `65535` (approx 65.5 ms, suitable for max range ~4m).
    *   **Interrupts**: None. Used solely for polling the count value.

## 3. Software Module (`Hardware/bsp_sr04.c` & `.h`)
*   **Variables**:
    *   `static volatile uint32_t t_start = 0;`
    *   `static volatile float sr04_distance = 0.0f;`
*   **Functions**:
    *   `void SR04_Init(void)`: Starts `TIMER_SR04` and enables the ECHO pin interrupt.
    *   `void SR04_Trigger(void)`:
        *   Sets TRIG pin `HIGH`.
        *   Uses `delay_cycles` for ~10 us.
        *   Sets TRIG pin `LOW`.
    *   `float SR04_Get_Distance(void)`: Returns `sr04_distance`.
    *   `GROUP1_IRQHandler` (or respective GPIO port IRQ handler):
        *   On `RISING` edge of ECHO: Record `t_start = DL_Timer_getTimerCount(TIMER_SR04_INST)`.
        *   On `FALLING` edge of ECHO: 
            *   Record `t_end = DL_Timer_getTimerCount(TIMER_SR04_INST)`.
            *   Calculate `delta = (t_end >= t_start) ? (t_end - t_start) : (65535 - t_start + t_end)`.
            *   Calculate `sr04_distance = delta * 0.017f`.

## 4. Application Logic Integration
*   **Task Layer (`app/task.c`)**:
    *   Call `SR04_Init()` during system initialization.
    *   Call `SR04_Trigger()` in a periodic 50ms or 100ms task loop to continuously measure distance.
*   **UI Layer (`app/app_lcd.c`)**:
    *   In `LCD_Show_Proc()` under `case 2:` (Dashboard Page 2), render the value returned by `SR04_Get_Distance()` next to the "Dist:" label at coordinates `(270, 10)`.

## 5. Potential Trade-offs
*   The 10us delay in `SR04_Trigger()` is a blocking busy-wait. Given it is extremely brief (10 us), it will not meaningfully impact the RTOS/main loop timing.
*   Timer wraparound is handled gracefully by ensuring we only measure up to 65ms per cycle.
